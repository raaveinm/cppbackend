# Игровой сервера "собачка"

*languages: [en](README.md)*

## 1. Обзор проекта
Этот проект реализует игровой сервер на C++, предназначенный для обработки игровой логики, управления данными игроков и обслуживания HTTP-запросов. Он включает в себя функции для загрузки игровых конфигураций, обработки клиентских запросов и предоставления конечных точек мониторинга.

## 2. Стек технологий
*   **Язык**: C++20
*   **Система сборки**: CMake
*   **Управление зависимостями**: Conan
*   **Сеть**: Boost.Beast (подразумевается `http_server.cpp` и зависимость от Boost)
*   **Логирование**: Boost.Log
*   **Обработка JSON**: Boost.JSON
*   **Контейнеризация**: Docker
*   **Мониторинг**: Prometheus (с использованием Python веб-экспортера)

## 3. Архитектура
Игровой сервер состоит из нескольких ключевых компонентов:
*   **HTTP-сервер (`net/http_server.h/.cpp`)**: Обрабатывает входящие HTTP-соединения и отправляет запросы.
*   **Обработчик запросов (`net/request_handler.h/.cpp`)**: Обрабатывает конкретные HTTP-запросы, взаимодействуя с игровой моделью.
*   **Игровая модель (`model/model.h/.cpp`, `model/player.h`)**: Содержит основную игровую логику, структуры данных для игровых сущностей (например, игроков) и управление состоянием.
*   **Загрузчик JSON (`loader/json_loader.h/.cpp`, `loader/boost_json.cpp`)**: Отвечает за загрузку игровых конфигураций и данных из JSON-файлов с использованием Boost.JSON.
*   **Утилиты (`util/sdk.h`, `util/tagged.h`, `util/logging.h/.cpp`, `util/token_generator.h`, `util/ticker.h`)**: Предоставляет общие утилиты, такие как логирование, генерация уникальных идентификаторов и механизмы синхронизации.

## 4. Система сборки
Проект использует CMake в качестве системы сборки, управляя компиляцией исходных файлов C++ и связыванием зависимостей. Conan интегрирован для обработки сторонних зависимостей C++, обеспечивая согласованную среду сборки.

В проекте используется система сборки CMake, управляющая компиляцией исходных файлов C++ и связыванием зависимостей. Для управления сторонними библиотеками C++ интегрирован менеджер пакетов Conan, обеспечивающий воспроизводимость среды сборки.

## 5. Запуск и развертывание

### Требования

* [Docker](https://docs.docker.com/get-docker/) и [Docker Compose](https://docs.docker.com/compose/install/)

### Быстрый старт (Docker Compose)

Чтобы собрать и запустить весь стек (Game Server, Prometheus, Grafana, Node Exporter) в фоновом режиме:

```bash
docker compose up -d --build

```

Чтобы остановить все сервисы и удалить контейнеры:

```bash
docker compose down

```

### Сервисы и используемые порты

После запуска контейнеров будут доступны следующие эндпоинты:

| Сервис | Порт | Описание |
| --- | --- | --- |
| **Game Server** | `8080` | Основной HTTP API и статический веб-контент |
| **Prometheus Exporter** | `9200` | Метрики приложения, собираемые `web_exporter.py` |
| **Prometheus** | `9090` | База данных временных рядов и интерфейс метрик |
| **Grafana** | `3000` | Дашборды для визуализации метрик |
| **Node Exporter** | `9100` | Метрики оборудования и ОС хоста |

### Проверка работоспособности

Убедитесь, что сервер работает корректно, запросив список карт:

```bash
curl -X GET http://localhost:8080/api/v1/maps

```

---

### Локальная сборка (для разработки)

Если вы хотите собрать и запустить исполняемый файл локально без использования Docker:

1. **Установка зависимостей**:

```bash
pip install conan==1.62.0

```

2. **Конфигурация и сборка**:

```bash
conan install . --build=missing -s build_type=Debug -if build
cmake -B build -DCMAKE_BUILD_TYPE=Debug -DCMAKE_TOOLCHAIN_FILE=build/conan_toolchain.cmake
cmake --build build --target game_server

```

3. **Запуск сервера**:

```bash
./build/game_server -c data/config.json -w static -t 50

```

## 6. Мониторинг
Мониторинг настроен с использованием Prometheus. Конфигурация `prometheus.yml` указывает:
*   **Интервал сбора**: Метрики собираются каждые 30 секунд.
*   **Цели**:
    *   `node-exporter:9100`: Для метрик на уровне хоста.
    *   `game-server:9200`: Для метрик, специфичных для приложения, предоставляемых скриптом `web_exporter.py`.

Скрипт `web_exporter.py`, анализирует вывод игрового сервера (перенаправленный из `stdout`) и предоставляет соответствующие метрики в формате, совместимом с Prometheus, на порту 9200.

```text
game_server/
 ├── CMakeLists.txt                     # Главный файл сборки CMake

 ├── conanfile.txt                      # Зависимости C++ (Boost)
 ├── docker-compose.yml                 # Запуск инфраструктуры (Сервер, Prometheus, Grafana, Node-Exporter)
 ├── prometheus.yml                     # Настройки сбора метрик для Prometheus
 ├── web_exporter.py                    # Python-экспортер метрик из stdout сервера в Prometheus
 ├── src/                               # Исходный код C++
 │   ├── main.cpp                       # Точка входа в приложение
 │   ├── loader/                        # Модуль загрузки данных
 │   │   ├── boost_json.cpp             # Подключение реализаций Boost.JSON
 │   │   ├── json_loader.cpp            # Реализация загрузчика JSON-конфигов
 │   │   └── json_loader.h              # Заголовочный файл загрузчика
 │   ├── model/                         # Игровая модель и логика
 │   │   ├── model.cpp                  # Реализация объектов и состояния игры
 │   │   ├── model.h                    # Описание игровых сущностей и карт
 │   │   └── player.h                   # Логика и состояние игрока
 │   ├── net/                           # Сетевой слой (Boost.Beast)
 │   │   ├── http_server.cpp            # Реализация низкоуровневого HTTP-сервера
 │   │   ├── http_server.h              # Обработка сессий и сетевых соединений
 │   │   ├── request_handler.cpp        # Маршрутизация и обработка бизнес-запросов
 │   │   └── request_handler.h          # Заголовок обработчика запросов
 │   └── util/                          # Вспомогательные утилиты
 │       ├── logging.cpp                # Настройка логирования (Boost.Log)
 │       ├── logging.h                  # Логгер и форматирование JSON-логов
 │       ├── sdk.h                      # Платформозависимые/базовые макросы
 │       ├── tagged.h                   # Вспомогательная сильная типизация (Strong Types)
 │       ├── ticker.h                   # Игровой таймер/тик с регулярным интервалом
 │       └── token_generator.h          # Генерация токенов авторизации
```
